# MIRROR SOCIAL ENGINE — Worker v0.5 開発状況
更新: 2026-10-16

## 区分
- **実装済み（PR #2、ドラフト）**: ZIPから通常ソース8ファイルを復元。ZIP原本は保持。入力本文のUTF-8実バイト数を12KB以下に制限し、上限超過は413、不正UTF-8/JSONは400とする。D1の一時的な問い合わせ失敗は認証境界を変更せず503を返す。
- **テスト追加**: 従来の23+6件に加え、本文サイズ、不正文字、DB停止、Origin、HTTPメソッドなどの10件を追加（合計39件）。
- **CI**: PR時に通常ソースを優先し、Nodeテスト・監査・bootstrapとdryrun双方のWrangler --dry-runを実行する。Cloudflareへの通信による実デプロイはしない。
- **実運用**: 未デプロイ。Worker v0.5が本番で稼働していることを意味しない。

## 運用上の保護
- `main`、既存PWA/ブラウザ保存データ/正式MASTERは変更しない。
- Workerの既存ZIP・GitHub Actions・本番D1テーブルは削除/変更しない。
- OAuthやSNS公式APIの接続なし。実投稿コード・課金APIの実行なし。
- `ADMIN_TOKEN` が未設定なら保護された `/jobs` APIはロックされたまま（503）。
- `/channels` の10媒体は対応予定のdry-run能力のみを示し、noteは手動引き渡し。UIの11媒体計画と実投稿能力は異なる。

## 残る重大な課題（未解決）
1. D1のジョブ作成とイベント履歴書き込みは2ステートメントに分かれており、途中失敗時に履歴の整合性が崩れる可能性がある。次段階でD1のトランザクションを使った安全な一括更新を設計・検証する。
2. `processing` 状態で処理が止まったジョブの回収・再試行上限・デッドレター処理はまだ実装されていない。
3. D1実環境でのスキーマ/インデックス/制約確認、排他処理の並列検証は未実施。
4. Cronトリガーは未設定で、実際の予約スケジューリングは稼働していない。
5. 11媒体の実SNS投稿、公式API認証、媒体別の費用・規約調査は未完成。
6. Cloudflare Workerの本番コード更新・公開検証は実施していない。

## 次の合格条件
- D1トランザクションと並列起動の統合テスト、過去/未来日時、再試行・障害復旧・イベント履歴の整合性を検証する。
- 実Cloudflare D1への変更は別途レビューと明示承認を経る。
- 新しいPRをマージする前に、GitHub Actionsの全件PASSと差分レビューを確認する。

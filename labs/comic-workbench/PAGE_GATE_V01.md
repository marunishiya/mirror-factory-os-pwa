# Page QA Hard Gate v0.1 — 非Canon・試験実装

画像生成を速くする機能ではなく、検証できない工程を BLOCKED にする証拠ゲート。

## 対象
- page-gate.cjs : validatePlan（生成前） / validateCandidate（生成後）
- page-gate.test.cjs : 18の失敗・拒否・誤承認防止ケース。架空の人物とセリフのみ。
- 実行：node --test labs/comic-workbench/page-gate.test.cjs

## 何を止めるか
- 批評・原因調査依頼なのに画像生成を呼ぶ行為
- 正式MASTERの実画像参照・SHA照合証拠なしの作画
- SOURCE LOCKとページ識別の不一致
- 画角・感情の変化がないままの再生成
- 不合格原因と改善内容が空欄の再試行
- 2048×3072 / 2:3 に未達の候補、単純アップスケールによる偽の高解像
- 原画像から独立に転記されていない吹き出し本文・話者・コマ位置
- 人物原本との並置、尻尾、スマホ可読性、編集レビューが未完了
- 別の画像のQA結果の使い回し

## 重要な制限
- ChatGPT画像生成ツールには未接続。このモジュール単体ではツール起動を制御できない。実際に使うには呼出元のオーケストレーターがこのゲートを必須実行する必要がある。
- MASTER の真偽、顔一致、文字認識、漫画の感動は自動判定していない。提出された証拠の形式を検査するのみ。hashMatched / renderProvenance の真実性は外部の信頼できる工程で照合する必要がある。
- REVIEW_REQUIRED は「未提出の証拠項目なし」の意味のみで、Canon承認・完成・公開可能ではない。
- 現在の image-qa.js 等には400万画素上限があり、目標ページ2048×3072（約629万画素）を丸ごと取り込めない。高解像ページにはタイル処理や別の検査経路と実機メモリ検証が必要であり、無検証で上限を緩和しない。
- 正式MASTER画像や未公開本編をGitHubにコミットしない。

## 次の安全な検証
1. 端末で承認済みMASTERをユーザー確認の上読み取り専用取得し、実ファイルのSHAを計算。
2. SOURCE LOCKと漫画原稿を検査した上で生成前ゲートを接続。
3. 実画像について解像度・見た目・吹き出し・感情の人間レビューを別々に実施。
4. 現時点で成果は試験ゲートのみ。既存 main、公開PWA、Cloudflare、正式Canonは変更しない。公開やデプロイ、マージは別途明示承認が必要。

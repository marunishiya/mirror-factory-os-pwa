# Comic Workbench: offline render pipeline / 実作画へ接続する前の検証

## 実装済み（Draft PR #9に追加）
- offline-render-pipeline.cjs は、原稿JSONの生バイトからSHA-256を再計算し、計画に埋められたSHAとの一致を確認する。
- キャラクターMASTER画像の生バイトと、本人承認済みとして外部登録したSHAを比較する。JPEG/PNG原本のみを読み取り、元画像は保存・更新・公開しない。
- assessRetry に承認済み画像・試行上限・同一入力・前回失敗の修正対象を問い合わせる。通過後だけ validatePlan を実行。
- 無料のテストモードではネットワーク/API呼び出しを行わず、検証用1x1 PNGを生成する。実バイトからハッシュ・寸法を読み、assessResult と validateCandidate で必ず未完成扱いにする。
- 実画像の人物同一性、セリフ、吹き出し、編集評価、Android実機確認は未検証。チェックボックスやSHA一致だけでPASSとしない。

## 実行
node --test labs/comic-workbench/offline-render-pipeline.test.cjs
CIの既存Comic Workbench QAワークフローで実行。追加の新規API、課金、デプロイはなし。

## 実作画連携が未完成の理由と安全設計
- OpenArt連携はアカウント残高不足で有料モデルを使えないことを確認したが、今回はAPI実行していない。
- 現コードは mode=mock 以外で即BLOCKED。課金APIを誤って呼び出さない。
- 有料／別の実生成APIと接続する前に、本人の明示予算承認、送信対象ファイルの指定、ライセンス/個人情報/MASTERの扱い、実サービスへデータ転送の許可が必要。
- エンドツーエンドといっても「模擬出力の配線テスト」であり、本物の作画の実証ではない。
- 現在の画像QAはページ単位の2048x3072制約を使っている。将来はコマ単位の画像QAとページ全体合成QAを別々に実装・検証する。
- MASTERは実バイトハッシュを検証しているが、誰が承認したファイルかという外部台帳の真正性は技術的に未証明。アップロードや履歴変更で本人認証を偽装しない。
- JPG検査は現段階ではマジック/終端の最低限の形式検査であり、完全な画像デコード検査ではない。実際の生成ワークフロー導入までに強化する。

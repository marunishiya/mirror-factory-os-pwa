# Comic Workbench v0.1 — 試験導入（非Canon）

これは **marunishiya/mirror-factory-os-pwa の既存アプリから分離した試験用サブアプリ** です。
`main`、既存の`index.html`、サービスワーカー、ローカルストレージ、
正式CHARACTER MASTER、MIRROR SOCIAL ENGINE、Cloudflare環境には変更を加えません。

## 操作

- `labs/comic-workbench/index.html` をブラウザで開き、MIRRORデモ／卑弥呼デモから開始します。
- デモは**実際のCanon・制作済み画像を含まないテストデータ**です。
- 対象コマを選び、人物ID・セリフ（`話者ID | 相手ID | 台詞`）・必要な小道具・確認済みの手掛かりを編集し「このコマだけ保存」。
- 「QA再実行」で、データ上の不足・セリフ話者不一致・伏線早期露出・考証出典未設定を確認。
- 画像を見て目視確認した後に、完成画像の参照IDと4つの人間によるチェックを記録できます。
- ERRORがない場合だけ「検査済みとして承認・ロック」。承認したコマは改変せず、必要なら別IDの草稿を作ります。
- JSON保存／読込でデータを管理します。データは自動保存しません。別フォルダの正式MASTERは更新しません。

### 実行

静的ファイルのみで動作します。ブラウザが`file://`上のスクリプト読込を許可する場合、`index.html`を直接開けます。
GitHub Pages等の静的ホスティングにも対応していますが、**このブランチからの自動公開・自動デプロイは構成していません**。

テスト: `node --test labs/comic-workbench/engine.test.cjs`

### 作品別の安全ガード

- PROJECT MIRROR：`requiredClues` ／`visibleClues`／`hiddenClues`で伏線提示時期の形式的チェック。キャストと吹き出しは登録データに基づきチェック。人物画像の真偽を判定したとは**主張しません**。
- 卑弥呼の声：考証を`primary_source`（原典）、`archaeology`（考古学）、`reconstruction`（復元仮説）、`fiction`（ゲーム創作）の4区分に登録。出典が空ならWARNING。**研究資料の実物照合は未実施**。
- `canon.reference` は参照ラベルであり、正式MASTERの内容そのものではありません。既存ユーザー承認済みMASTERを勝手に補完・更新しません。
- 「承認」はこの試験ワークフロー内のコマロックです。**正式Canonの変更承認を意味しません**。

## セキュリティ・データ保持

- 静的アプリ・API呼び出しなし。`localStorage`、IndexedDB、Cookieには一切触れません。
- JSONを最大1MBに制限して読み込み、スキーマを検証。文字情報の描画は`textContent`で実施し、ユーザー入力をHTMLとして実行しません。
- 画像そのものは管理・添付されません。`assetRef`は記録用の文字列です。
- ページはブラウザ更新で未出力内容が消えるため、作業後にJSONファイルへ保存してください。
- 人による目視チェックの記録は自己申告。視覚QA・同一人物性の客観検査ではありません。
- 一度承認したコマは変更不可。変更したい場合は新しい下書きを作成し、旧コマを保持します。
- 各コマの差分監査ログは最新500件まで。過剰に溜まる前にJSONを書き出してください。

## v0.2 — 画像差分・MASTER参照ラボ（今回の追加）

`image-lab.html`に、編集前画像と編集後画像を読み込み、スマホでドラッグ選択したROI（修正可領域）に対する**画素レベルの変更量**を検証する画面を追加しました。
`index.html`の選択コマから作品ID／コマIDを引き継いで開けます。

1. 参考用CHARACTER MASTER画像（任意）、修正前のコマ画像、修正後のコマ画像を**自分の端末から**読み込みます。MASTERは比較対象として画面表示するだけで**自動保存・書き込み・送信なし**。
2. 修正前画像の上をドラッグして、変更を許可する領域を指定します。指定範囲外の画素差分が0.5%を超える場合はFAIL、画像が同一の場合はNO_CHANGE、閾値内ならPASSです。
3. 「PASS」は**画素差分検査だけ**の判定です。人物同一性・服装・吹き出し／台詞・歴史考証・伏線は人が目視確認する必要があります。
4. 検査後に、画像内容を特定するSHA-256、寸法、ROI、差分統計、目視チェックの自己申告結果を含む**画像なしJSON**を保存できます。ユーザー承認済みCanon自体の変更はできません。
5. 不一致の箇所は赤色で可視化されます。作画指示書のテキストも生成できますが、生成AIモデルや局所インペインティングは未接続です。

### 制限とリスク

- PNG/JPEG/WebPのみ、ファイルあたり最大10MB、画像あたり400万画素。異なる寸法は比較不可。JPEGは再エンコードによる画素差分を生じます。
- ブラウザのメモリ上で作業し、元画像・修正画像・MASTER画像を永続保存しません。ブラウザを閉じる前に必要なレポートを書き出してください。
- ROIの閾値は初期段階の暫定値（RGB/Alphaの最大チャンネル差24、範囲外0.5%、修正可能面積60%未満）。漫画ページで実測して調整する必要があります。
- SHA-256はファイルの同一性を示すハッシュであり**顔認識・履歴改ざん防止署名ではありません**。レポートJSONは利用者が編集できる通常のファイルです。
- 自動の「元画像と同じ人物だ」という判断は未実装。正式MASTERの実ファイルはこの試験版に埋め込まれていません。
- セキュリティ／プライバシー：ブラウザ内のCanvasとWeb Cryptoのみ使用し、ネットワークAPIも外部SDKも用いません。画像はGitHubへ追加しないでください。
- 既存のMIRROR FACTORY OSおよび『卑弥呼の声』のゲーム本体とは未統合。ドラフトPRのみです。

## v0.3 — 指定領域のみ合成するPNG書き出し

v0.2の画素差分だけでなく、`image-lab.html`に **「指定範囲だけ合成してPNG保存」** を追加しました。

- 元画像と修正候補は同じ画像寸法である必要があります。
- 修正候補のうちドラッグ指定したROI領域だけを、元画像のRGBA画素にコピーしてPNGとして書き出します。
- **ROI外の画素は元画像のピクセルデータと完全一致**します（合成コードは元画像オブジェクトを変更しません）。
- 出力PNGのSHA-256を生成し、候補画像とは別のハッシュで記録。`report.result`は候補画像の画素検査、`report.composite.compositeVerdict`は実際に保存した合成PNGの検査結果です。
- 指定範囲に変化がない場合は「変更なし」として合成を中止します。
- 画像や対象コマが切り替わった場合、前の手動確認チェックを引き継ぎません。
- 異なる画像の境界を単純に接合するため、色・模様・影のつながりに不自然さが残る場合があります。自動修復モデルによるシームレスなインペインティングとは異なります。
- 原本ファイルと承認済みマスターは読み込むだけで書き換えません。**ユーザーがローカルで選択した画像のみ**を合成し、作成PNGをダウンロードします。
- 出力画像とQAのJSONは別々のファイルです。PNG保存後に「検査レポートJSON保存」も行ってください。
- 実データでのブラウザ操作検証・モデルによる画像品質評価・本番統合は未実施です。

GitHub Actionsにおいて、既存の構造化QA、画像差分、ROI合成および保護領域検査を含む **41件のNodeテストが成功**しています。ブラウザの実画面タッチ操作テストは今後の項目です。

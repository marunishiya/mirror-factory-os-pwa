# Comic Workbench v0.1 — 試験導入（非Canon）

これは **marunishiya/mirror-factory-os-pwa の既存アプリから分離した試験用サブアプリ** です。
`main`、既存の`index.html`、サービスワーカー、ローカルストレージ、
正式CHARACTER MASTER、MIRROR SOCIAL ENGINE、Cloudflare環境には変更を加えません。

## 操作

- `labs/comic-workbench/index.html` をブラウザで開き、MIRRORデモ／卑弥呼デモから開始します。
- デモは**実際のCanon・制作済み画像を含まないテストデータ**です。
- 対象コマを選び、人物ID・セリフ（`話者ID | 相手ID | 台詞`）・必要な小道具・確認済みの手掛かりを編集し「このコマだけ保存」。
- 「QA再実行」で、データ上の不足・セリフ話者不一致・伏線早期露出・考証出典未設定を確認。
- 画像を見て目視確認した後に、完成画像の参照IDと4つの人間によるチェックを記録できます。
- ERRORがない場合だけ「検査済みとして承認・ロック」。承認したコマは改変せず、必要なら別IDの草稿を作ります。
- JSON保存／読込でデータを管理します。データは自動保存しません。別フォルダの正式MASTERは更新しません。

### 実行

静的ファイルのみで動作します。ブラウザが`file://`上のスクリプト読込を許可する場合、`index.html`を直接開けます。
GitHub Pages等の静的ホスティングにも対応していますが、**このブランチからの自動公開・自動デプロイは構成していません**。

テスト: `node --test labs/comic-workbench/engine.test.cjs`

### 作品別の安全ガード

- PROJECT MIRROR：`requiredClues` ／`visibleClues`／`hiddenClues`で伏線提示時期の形式的チェック。キャストと吹き出しは登録データに基づきチェック。人物画像の真偽を判定したとは**主張しません**。
- 卑弥呼の声：考証を`primary_source`（原典）、`archaeology`（考古学）、`reconstruction`（復元仮説）、`fiction`（ゲーム創作）の4区分に登録。出典が空ならWARNING。**研究資料の実物照合は未実施**。
- `canon.reference` は参照ラベルであり、正式MASTERの内容そのものではありません。既存ユーザー承認済みMASTERを勝手に補完・更新しません。
- 「承認」はこの試験ワークフロー内のコマロックです。**正式Canonの変更承認を意味しません**。

## セキュリティ・データ保持

- 静的アプリ・API呼び出しなし。`localStorage`、IndexedDB、Cookieには一切触れません。
- JSONを最大1MBに制限して読み込み、スキーマを検証。文字情報の描画は`textContent`で実施し、ユーザー入力をHTMLとして実行しません。
- 画像そのものは管理・添付されません。`assetRef`は記録用の文字列です。
- ページはブラウザ更新で未出力内容が消えるため、作業後にJSONファイルへ保存してください。
- 人による目視チェックの記録は自己申告。視覚QA・同一人物性の客観検査ではありません。
- 一度承認したコマは変更不可。変更したい場合は新しい下書きを作成し、旧コマを保持します。
- 各コマの差分監査ログは最新500件まで。過剰に溜まる前にJSONを書き出してください。

## v0.2 — 画像差分・MASTER参照ラボ（今回の追加）

`image-lab.html`に、編集前画像と編集後画像を読み込み、スマホでドラッグ選択したROI（修正可領域）に対する**画素レベルの変更量**を検証する画面を追加しました。
`index.html`の選択コマから作品ID／コマIDを引き継いで開けます。

1. 参考用CHARACTER MASTER画像（任意）、修正前のコマ画像、修正後のコマ画像を**自分の端末から**読み込みます。MASTERは比較対象として画面表示するだけで**自動保存・書き込み・送信なし**。
2. 修正前画像の上をドラッグして、変更を許可する領域を指定します。指定範囲外の画素差分が0.5%を超える場合はFAIL、画像が同一の場合はNO_CHANGE、閾値内ならPASSです。
3. 「PASS」は**画素差分検査だけ**の判定です。人物同一性・服装・吹き出し／台詞・歴史考証・伏線は人が目視確認する必要があります。
4. 検査後に、画像内容を特定するSHA-256、寸法、ROI、差分統計、目視チェックの自己申告結果を含む**画像なしJSON**を保存できます。ユーザー承認済みCanon自体の変更はできません。
5. 不一致の箇所は赤色で可視化されます。作画指示書のテキストも生成できますが、生成AIモデルや局所インペインティングは未接続です。

### 制限とリスク

- PNG/JPEG/WebPのみ、ファイルあたり最大10MB、画像あたり400万画素。異なる寸法は比較不可。JPEGは再エンコードによる画素差分を生じます。
- ブラウザのメモリ上で作業し、元画像・修正画像・MASTER画像を永続保存しません。ブラウザを閉じる前に必要なレポートを書き出してください。
- ROIの閾値は初期段階の暫定値（RGB/Alphaの最大チャンネル差24、範囲外0.5%、修正可能面積60%未満）。漫画ページで実測して調整する必要があります。
- SHA-256はファイルの同一性を示すハッシュであり**顔認識・履歴改ざん防止署名ではありません**。レポートJSONは利用者が編集できる通常のファイルです。
- 自動の「元画像と同じ人物だ」という判断は未実装。正式MASTERの実ファイルはこの試験版に埋め込まれていません。
- セキュリティ／プライバシー：ブラウザ内のCanvasとWeb Cryptoのみ使用し、ネットワークAPIも外部SDKも用いません。画像はGitHubへ追加しないでください。
- 既存のMIRROR FACTORY OSおよび『卑弥呼の声』のゲーム本体とは未統合。ドラフトPRのみです。

### 検証

## v0.3 — 指定領域のみ合成するPNG書き出し

v0.2の画素差分だけでなく、`image-lab.html`に **「指定範囲だけ合成してPNG保存」** を追加しました。

- 元画像と修正候補は同じ画像寸法である必要があります。
- 修正候補のうちドラッグ指定したROI領域だけを、元画像のRGBA画素にコピーしてPNGとして書き出します。
- **ROI外の画素は元画像のピクセルデータと完全一致**します（合成コードは元画像オブジェクトを変更しません）。
- 出力PNGのSHA-256を生成し、候補画像とは別のハッシュで記録。`report.result`は候補画像の画素検査、`report.composite.compositeVerdict`は実際に保存した合成PNGの検査結果です。
- 指定範囲に変化がない場合は「変更なし」として合成を中止します。
- 画像や対象コマが切り替わった場合、前の手動確認チェックを引き継ぎません。
- 異なる画像の境界を単純に接合するため、色・模様・影のつながりに不自然さが残る場合があります。自動修復モデルによるシームレスなインペインティングとは異なります。
- 原本ファイルと承認済みマスターは読み込むだけで書き換えません。**ユーザーがローカルで選択した画像のみ**を合成し、作成PNGをダウンロードします。
- 出力画像とQAのJSONは別々のファイルです。PNG保存後に「検査レポートJSON保存」も行ってください。
- 実データでのブラウザ操作検証・モデルによる画像品質評価・本番統合は未実施です。

GitHub Actionsにおいて、既存の構造化QA、画像差分、ROI合成および保護領域検査を含む **41件のNodeテストが成功**しています。ブラウザの実画面タッチ操作テストは今後の項目です。


## v0.4 — MASTER参照台帳（端末内、読み取り専用）

`authority.js` および`image-lab.html`に、**原本画像のハッシュ（SHA-256）を使って取り違えを防ぐ参照台帳**を追加しました。7つの外部OSSのコードや学習済みモデルは取り込んでいません。

### 操作（現時点では試験版）

1. `image-lab.html`で作品（MIRROR／卑弥呼の声）を選択します。
2. 端末から承認済みのCHARACTER MASTER等の**元画像**を選びます。**画像そのものはWebアプリやGitHubにアップロードされません**。
3. 該当する人物ID（例: `sane`）、区分、表示名、確認メモを入力。ユーザーが承認済み原本であることを実物と照合した後でのみ、「この画像を確認した」チェックを入れて参照登録します。
4. 「参照台帳JSON保存」を使ってハッシュ・寸法・ファイル名だけを書き出します。JSONはブラウザから自動保存されず、後で再び「参照台帳JSON読込」で読み込みます。
5. 後日、同じ人物IDを指定して原本画像を再び選択すると、**ファイル内容と寸法・サイズの一致／不一致**を判定します。同じ見た目で再圧縮した画像も不一致になります。
6. 作品または人物IDの参照が違う場合、本人の確認結果として扱いません。登録済みの同IDの画像を別ハッシュで自動上書きしません。

**重要**：SHA-256で検証できるのは「選択した画像ファイルが台帳に登録されたファイルと同じか」という点です。台帳そのものがユーザー入力に基づく自己申告情報であり、署名・第三者証明・正式Canon認証を含みません。利用者が登録した原本画像が「正式にユーザー承認済み」かは別途確認が必要です。AIによる異なるポーズ間の顔・体型・衣装照合は未実装です。

### レポートとQA

- 画像検査JSONには `authorityBinding`（NO_REGISTRY／UNREGISTERED／NO_IMAGE／MATCH／MISMATCHなど）と `masterFileMatched`を付加します。
- 台帳を読み込んだとき、該当画像のハッシュが一致するまで人物同一性の目視確認チェックを有効化しません。
- 原本画像・作品・人物IDが変わるたびに前のチェック結果をクリアします。**一度押したチェックが別の画像に自動で引き継がれない**ようにしました。
- 登録・照合は端末メモリ内のみで実施。実MASTER画像もJSON台帳もGitHubリポジトリへ追加しません。原本画像はローカル読み込み専用です。
- 画素QAは、ROI外だけを変更した画像がたとえ全体の0.5%未満であってもPASSにしないよう改善しました。
- `authority.test.cjs`で作品分離・上書き拒否・不正データ・一致不一致・JSON衛生を検査します。CIコマンドは `node --test labs/comic-workbench/*.test.cjs` です。

### 未実施

- 実際のMIRROR／卑弥呼の公式MASTERをこのPRへ持ち込むこと（**意図的に未実施**）
- 異なるカメラアングルや表情の同一人物自動判定

## v0.5 — **配布・スマホ実行ができるオフライン版**（2026-10-20）

これまでは分離した複数ファイルのGitHubソースのみでした。新しい`build-portable.cjs`でHTML内にJavaScriptを埋め込み、ネットワーク・外部パッケージに依存しない**オフライン配布ファイル2点**を生成できます。

- `portable-dist/index.html`：漫画コマの設計・編集・構造化QA
- `portable-dist/image-lab.html`：MASTERの読み取り専用参照、差分・局所合成、PNG・レポートJSON保存
- `portable-dist/使い方.txt`：スマホ操作の案内

### 配布ファイルの入手

1. PR #7の最新コミットの **Comic Workbench QA + Offline Package (no deploy)** が成功していることを確認します。
2. Actionsの実行結果下部 `Artifacts` から `comic-workbench-offline-v0.5`をZIP形式で取得（GitHubへのログインが必要な場合があります）。
3. ZIPを解凍し、2つのHTMLを同じフォルダに配置して、ChromeなどのJavaScript対応ブラウザで開いてください。サイトへの公開・公開Pages設定は行っていません。
4. まず `image-lab.html`の**「練習用画像で試す」**ボタンで架空のテスト画像を生成し、`「修正前後を比較する」→「指定範囲だけ合成してPNG保存」`で動作を確認してください。正式MASTERを試すのは動作が分かってからです。

Chrome/Androidの一部アプリ内プレビューはローカルHTMLの実行を制限する場合があります。そうした環境ではPCのChrome/Edgeをご利用ください。ブラウザで動かない場合でも、HTMLを送信するために公開サイトへ正式MASTER画像をアップロードしないでください。

### 新しい品質改善

- Web Crypto APIが使えない一部ローカル環境でも、独立実装のSHA-256フォールバックが動きます（`sha256.js`）。ハッシュは公式FIPSテストベクターとNode cryptoの計算結果で検証。
- 「練習用画像で試す」ボタンはブラウザ内で非Canonの画像2枚を自動生成し、修正ROIを設定します。ユーザーの原本や台帳は自動公開しません。
- すべての.jsがHTML内に埋め込まれるため、HTMLを開くだけで依存スクリプトの404エラーは発生しません。
- PRのCIはNodeの各ユニットテスト、SHA-256、同梱構造の検証に加え、Artifacts ZIPを**デプロイせず**作成します。
- 対応画像は各10MB／400万画素まで。原本はブラウザメモリ上のみ。ブラウザを閉じると消えるので必要な成果物は都度ダウンロードしてください。

### 重要な限界

AIによる描画、異なるポーズの顔一致判定、ユーザー承認の公式認定、GitHub Pages公開、既存MIRROR FACTORY OSの`main`へのマージは行っていません。実装したのは**人が画像を選び、部分合成・QA・出力できる試験用の実行アプリ**です。実際のスマホ機種・ブラウザごとに動作確認が必要です。


## v0.6 — 既存MIRROR FACTORY OSとの読み取り専用連携

従来の`main`、正式MASTER、ブラウザ上の制作データを保護したまま、別ブランチのFACTORY OS原稿保管庫に **「制作ラボを開く」**リンクを追加しました。**ドラフトPRなので現行の公開PWAにはまだ反映していません**。

### 連携の入口（統合後）

1. 同じブラウザ・同じHTTPSオリジンでFACTORY OSを開き、**原稿保管庫 → 制作ラボを開く**。
2. ラボの「この端末のFACTORY OSを読み込む」を押すと、`mirror_factory_os_v09`を **getItemのみ** で読みます。画像用IndexedDBは読まず、書きません。ブラウザが同一オリジンでなければ端末保存を取得できません。
3. ページを選び「選択ページを草稿コピーにする」を押します。既存のコマ割り・セリフ順が整合する場合だけ各コマに分割します。不整合や未登録の場合、元のセリフを変更せず**ページ単位の要確認草稿**として取り込みます。
4. `assetRef`や画像MASTERの実体、元FACTORYの「正式承認済み」チェックは移しません。人物画像は別途ユーザーが照合してください。
5. ラボで編集し、必要な時だけ**独立した漫画ラボJSON**をダウンロードします。FACTORY OSのlocalStorage、IndexedDB、SOURCE LOCKは**一切書き戻しません**。

### オフラインZIPでも利用可能

オフライン版（`index.html`）は、既存OSから書き出した**バックアップJSON**を選んでも原稿だけを取り込めます（32MB以下）。バックアップに画像base64を含んでいても、ラボの草稿には画像データを転写しません。大容量バックアップではデータの読込上限に当たるため、将来的な段階的取込を検討します。

### 作品ごとの注意

- **PROJECT MIRROR**：SOURCE LOCKの文字・話者・コマ配列を保持。厳密一致しない既存データは自動修復せず拒否か要確認にします。未対応の正式演出・考証を想像で埋めません。
- **卑弥呼の声**：既存の卑弥呼ゲーム本体からの自動接続は行っていません。これまでの独立した非Canonデモ・歴史考証のQAのみで継続し、正式な資料・人物MASTERは手動の読み取り専用参照が必要です。
- **データ安全**：読込はユーザー操作開始時のみ。自動公開・クラウド送信・課金・保存先データ上書きはありません。ブラウザ上のラボ草稿はJSON保存を忘れると消える可能性があります。

### 検証

- `factory-bridge.test.cjs`：選択コマへの割付、SOURCE LOCK、話者ID、未知話者、元データ不変、バックアップの画像除外など
- `factory-integration.test.cjs`：現行FACTORY OSのlocalStorageキー・IndexedDBキー・LOCK関数とリンクの保持
- GitHub Actionsではオフライン版のHTMLを自動生成し、**配布ZIPを成果物として保存**（本番公開ではない）。
- ローカルChromiumのスマホ相当画面に配布HTMLを読み込み、テスト用のFACTORYデータで **ページ一覧→選択→草稿コピー→QA→JSON出力** を通し、取込前後で元データが同じであることを確認。バックアップJSON経由の取込も成功。実際のAndroid実機での操作確認と実際の承認済みデータを使った試験は未実施。

### 統合前の最終ゲート

- 既存の`main`へマージする前に明示的な承認が必要。現行GitHub Pages PWA、保存領域、Worker、SNSは変更しません。
- 公式Canon・MASTERの変更や本番デプロイ、実SNS投稿、課金をこのPRから自動実行しません。


## v0.7 — 原稿の1文字を守る SOURCE LOCK照合・誤承認防止

**改善課題**：FACTORY OSのSOURCE LOCK原稿をコピーした後、ラボ内で1文字や話者IDが書き換わっても、従来のラボは画像参照と手動チェックが揃えばそのコマを承認できる可能性がありました。また、セリフ編集欄の`trim()`によって原稿の文頭・末尾の空白や区切り記号が変形する余地がありました。

### 今回実装した防止策

- 元のFACTORY原稿の**全文（話者名・本文・行順）**、FACTORYのSOURCE LOCKチェックサム、取り込み時の話者ID対応表、コマ別の確定セリフを、編集対象とは別の`sourceInfo`領域に保持します（画像MASTERは持ち込みません）。
- `W.sourceReport(doc,panelId)` が、現在のコマのセリフ・話者・順序を取り込み時の参照情報と**完全一致**で確認します。未ロックの原稿、参照情報の欠落、元のチェックサムの不整合は`SOURCE_UNVERIFIED`、セリフの差は`DIVERGED` と明示します。
- **SOURCE未合格のコマはラボ内での承認・作画指示書生成を拒否**します。別プロジェクトの通常デモにはこの追加ゲートを適用しません。
- 「**確定セリフだけ元に戻す**」ボタンで、FACTORY原稿からの読取時の話者・本文に復元できます。元FACTORY保存データや他のコマを変更しません。
- `dialogue-codec.js`が、編集していないセリフを原文のまま保持します。文頭末尾のスペース、パイプ文字`|`、一部の改行を含む本文で、場面メモの編集だけを理由に変形させません。
- 構図・セリフ・画像参照・小道具・伏線等を変更すると、同じコマの**以前の目視QA結果をすべて失効**させます。新しい画像と原稿を照合し直す必要があります。
- SOURCE LOCKの合格は**構造化テキストの一致**に限られます。画像そのものの顔・衣装・吹き出しが正しいという意味ではありません。

### 安全上の限界

- FACTORYの既存`sourceLockHash`は32-bit FNV由来の差分検出値です。悪意ある改ざんを防ぐ電子署名ではありません。`sourceInfo`を含むJSONはユーザーが編集できるため、形式上のSOURCE一致を**公式Canonの認証**とは扱いません。
- 同じ内容のまま画像・構図を変更した場合も人による画像QAは再実施が必要です。
- SOURCEから分岐した新たなコマは元ページのコマとの対応が未定義になるため、勝手にSOURCE承認を引き継ぎません。
- ゲーム『卑弥呼の声』の正式Canon・考古学的裏付けはこのチェックでは検証されません。
- **GitHubドラフトPRのまま**で、本番PWAに未反映。`main`、`sw.js`、Cloudflare、正式MASTER、端末内の本番保存データを変更しません。

### 試験

`node --test labs/comic-workbench/*.test.cjs` で、セリフの1文字改変・話者入替・順序・原文空白・チェックサム・QA失効・元原稿復元・他コマ不変等を追加で検証しています。


## v0.8 — 有償製品化の前段階：データ復旧と商品化ゲート

**販売開始ではありません。** β版のデータ喪失リスクを小さくし、個人制作者／小規模漫画制作チームが本当に代金を支払いたくなる品質条件を策定しています。詳細は `COMMERCIAL_READINESS.md` を参照。

### 今回の実装

- `draft-vault.js`：**利用者が明示的に有効化した場合のみ**端末に漫画ラボ草稿の保存済みスナップショットを残す。現在＋前回の2世代、SHA-256で偶発破損を検出、選択コマを復元。独立した名前空間 `comic_workbench_private_drafts_v1:*`を使用し、FACTORY OSの保存キーやIndexedDBは変更しない。
- UIに「端末内の復旧保存を有効化」「今後の自動保存を停止」「最新／ひとつ前を復元」「復旧データ2件を消去」を追加。長い操作群はスマホで折り畳んで表示する。初回は無効／自動復元しない／元の正式Canon承認にはしない。
- 保存対象は「このコマだけ保存」「確定原稿を戻す」「承認」「新規草稿」など、**アプリ側で確定した編集結果のみ**。フォーム内でタイプ中の未保存文字やMASTERの画像バイナリは保存対象外。
- 端末がストレージを提供しない場合、書込み容量不足、破損データがある場合は**保存成功と偽らない**。手動JSON保存を推奨。JSON出力せず端末を閉じようとする場合の未保存警告も追加。
- 同意を解除した場合、過去の復旧データは残るので「復旧データを消去」で明示的に削除する。共有端末では同意を有効にしない。
- `draft-vault.test.cjs`で同意、キー分離、2世代、チェックサム、容量不足、古い草稿保持、明示消去、人物データの不変性を検証。

### プライバシーの限界

- **暗号化、ユーザー認証、悪意ある改ざん対策、端末間のクラウド同期はありません。** 同じブラウザ・同じオリジンを使う別のJSコードにも端末保存の読み取り権限がある可能性があるため、商用公開前に専用オリジン・認証・ブラウザセキュリティ・データ削除の設計を確認します。
- ブラウザの保存データ削除、端末紛失、プライベートモード等では復旧できません。**外部JSONファイルとして定期的に保管**してください。
- これは「編集途中の草稿を失いにくくする」機能です。正式MASTERとFACTORY OSの原本バックアップを代替しません。
- 市場の存在・価格受容・商用OSS権利・実Android端末での安定性は未検証。有償販売の可否は`COMMERCIAL_READINESS.md`のゲートで判定します。


## v0.9 — コマ画像を見ながら吹き出し・話者・セリフを照合する

### 使い方（オフライン試験版）

1. 漫画ワークベンチで対象ページを開き、**JSON保存**する。`balloon-lab.html`へ移動してそのJSONを読み込む。初めてなら「練習用サンプルを作る」で非Canon画像と発言を生成する。
2. コマを選び、完成画像のPNG/JPEG/WebPを端末から選ぶ（上限10MB・400万画素）。原本画像はブラウザのメモリでのみ扱う。
3. 確定セリフが上に表示されるので、それぞれ対応する吹き出しの中心を**人がタップ**する。吹き出しが複数ある場合は右→左・上→下などその画像に適切な読み順を自分で確認する。
4. 画像上の人物を見て、**話者を選び**、画像で実際に読める文字を**1文字まで転記**し、目視チェックを付ける。原稿の話者・本文を観測欄へ自動コピーしない（「確認したつもり」の防止）。
5. 「人が記録した注釈を照合する」で原稿との差分、話者ID違い、未入力、範囲外、重なり、横並びでの右→左ヒントを検査。レポートをJSON保存できる。

### 結果の意味

- `INCOMPLETE`：吹き出しの位置／話者／転記／目視記録が足りない
- `MISMATCH`：人が入力した話者IDまたは転記文字と確定原稿に不一致
- `BLOCKED`：FACTORY取込原稿のSOURCE LOCKが未合格（入力が一致しても認定不可）
- `ANNOTATIONS_CONSISTENT`：**人が入力した注釈データ**と確定原稿が一致。「完成画像の正しさをAIが検査済み」ではない
- `RTL_POSITION_HINT` / `OVERLAPPING_MARKERS`：空間的な確認を促すヒント。吹き出しを自動検出した結果ではない

**本当の意味での画像内容自動QAはまだ実装していません。** OCR、吹き出し自動検出、画像内の尻尾先端と話者の自動対応、表情をまたぐ人物同一性判定は未実装です。手動注釈からしか判定できないため、`imageAnalyzedByAI:false`、`ocrPerformed:false`、`visualImageVerified:false`、`canonApproved:false`をすべてのレポートに明記します。

### 独立性とセキュリティ

画像ファイルはレポートに含まず、SHA-256・寸法・ファイルサイズのみ。コマまたは画像を変更すると、それまでの注釈を破棄して誤流用を防ぎます。画像や原稿を外部API、画像モデル、GitHubへ送らず、GitHub本番の正式MASTERやSOURCE LOCKには書き戻しません。現行の実装にはログイン・権限管理・OCR・商用課金を含みません。ブラウザ内のメモリのみのため、必要な検証証跡は都度ダウンロードしてください。

### 商用化の判定

この機能の実装だけでは、`COMMERCIAL_READINESS.md`の「自動画像認識QA」は合格にできません。人の負担削減・操作性を別途テストし、誤ったPASSを出さないための境界を確認します。
